# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scratchpad follows the Windows apps light/dark setting live, renders a "Dark Post-it" palette everywhere in dark, and offers a Follow Windows / Light / Dark override in Settings that Reset to defaults also resets.

**Architecture:** `Scratchpad.Core` decides *which* theme (preference + Windows registry value → Light/Dark) and persists the preference (`ThemeStore`), all unit-tested. The Shell has two `ResourceDictionary` files (`Themes/Light.xaml`, `Themes/Dark.xaml`) merged into `Application.Resources`; a Shell `ThemeManager` swaps them and raises `ThemeChanged`. **Principle that keeps light mode identical to today:** `Light.xaml` holds only today's Post-it brushes (plus one alias, below); everything that today uses Windows' system colours (scrollbars, context menu, combo boxes, Settings window, preview elements) is themed *only* in dark — via implicit styles that exist only in `Dark.xaml`, or via code that sets resource references in dark and `ClearValue`s them in light.

**Tech Stack:** C# / WPF (.NET Framework 4.8), `Scratchpad.Core` (netstandard2.0, `Microsoft.Win32.Registry` already referenced), xUnit (net10.0), Markdig.Wpf 0.5.0.1.

**Spec:** `docs/superpowers/specs/2026-11-02-dark-mode-design.md`

## Global Constraints

- Registry: `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize`, value `AppsUseLightTheme` (DWORD, `0` = dark). Missing/unreadable/non-int → treat as light.
- Default preference: Follow Windows. Persisted to `%LOCALAPPDATA%\Scratchpad\theme.json`, same best-effort atomic pattern as `FontFamilyStore`; unreadable/invalid → Follow Windows.
- Dark palette (spec table): Background `#3A3420`, Toolbar `#2F2A19`, Border `#5A5130`, Button `#4A4228`, ButtonPressed `#8A7220`, Text `#F3E6A6`. Light values unchanged.
- Settings picker labels exactly: `Follow Windows`, `Light`, `Dark`. Reset prompt exactly: `Reset all settings to their defaults?`
- No new NuGet dependencies. Light mode must look exactly as today.
- Brushes used by switchable XAML must be referenced with `DynamicResource`, never `StaticResource`.

## Review Focus

- **Light mode regression:** with the theme Light (or Windows light), every surface must look exactly as before this branch — in particular the Settings window, combo boxes, scrollbars, editor context menu, and preview (no lingering dark local values after switching dark → light).
- **Live switch while hidden / in preview / with Settings open:** a Windows theme change (or picker change) while the main window is hidden in the tray, while the preview is showing, or while Settings is open must re-theme all of them without a restart; the next show must not show stale colours.
- **`SystemEvents.UserPreferenceChanged`** is a static event: must be unsubscribed on exit (tray Exit) and must be marshalled to the UI dispatcher before touching WPF.
- **Startup order:** the theme must be applied before `MainWindow` is constructed (no light flash in dark), and a corrupt `theme.json` or missing registry value must never throw out of startup.
- **Reset with Settings open:** after Reset, the theme picker shows `Follow Windows` and the app is re-themed accordingly, and no intermediate `ThemePreferenceChanged` is raised while the picker is re-selected programmatically.

**Interfaces:**
- Consumes: Task 1 and 2 types.
- Produces (`Scratchpad.ThemeManager : IDisposable`):
  - `ThemeManager(ThemeStore store, IPersonalizeRegistry registry)`
