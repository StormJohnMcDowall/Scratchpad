# UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the main window look finished:
- a real app icon (tray, window/taskbar, .exe);
- icon toolbar buttons with tooltips;
- breathing room around the note text;
- a visible window edge.

**Architecture:** All Shell-side (WPF) and cosmetic, so there is nothing new in `Scratchpad.Core` to unit-test.
- The icon is generated by a stdlib-only Python script that is checked in, so it can be regenerated.
- It is embedded as a WPF `Resource` and as the `ApplicationIcon`.
- The toolbar glyphs come from the built-in Windows font *Segoe MDL2 Assets*.
- The text padding is one shared `Thickness` resource, used by both the editor and the preview.

**Tech Stack:**
- WPF on .NET Framework 4.8. It only compiles in this sandbox; it can't run here.
- Python 3 (stdlib only: `struct`, `zlib`) for the icon generator.

**Spec:** a small change agreed in chat on 2026-11-03, so there is no spec document. Items 1–5 of the polish review, reproduced:

1. **App icon:** a small Post-it in the app's palette. It replaces `SystemIcons.Application` in the tray and is also the window/taskbar icon and the .exe icon.
2. **Icon toolbar buttons:** Preview, Always on top, Date, smaller/larger text, Settings and hide all become Segoe MDL2 Assets glyphs. This fixes crowding and the overflow under the hide button at narrow widths, and leaves empty toolbar space for dragging.
3. **Tooltips with shortcuts on every toolbar button.**
4. **About 10px of space around the text** in the editor and the preview. The editor's scroll-to-character maths has to subtract the padding.
5. **A 1px window border** so the note doesn't blend into a light background.

## Global Constraints

- No new NuGet dependencies, and no Python packages beyond the stdlib.
- **Light mode keeps its look** except for the four intended changes: icon, toolbar glyphs, padding, border. Anything dark-only goes in `Themes/Dark.xaml`.
- The icon must never stop the app starting. A tray-icon load failure falls back to `SystemIcons.Application`.
- Glyph font: exactly `Segoe MDL2 Assets` (present on Windows 10 and 11).

## Review Focus

1. **Dark-mode tooltips.** WPF tooltips use system (light) colours, so seven new tooltips would be white boxes on the dark note. Add a dark-only implicit `ToolTip` style (Task 2).
2. **Keep-your-place and double-click accuracy after the padding change.**
   - The preview's margin must sit *inside* the scrolled content, on `PreviewViewer`. That keeps `PreviewNavigator`'s extent coordinates consistent.
   - The editor's `ScrollEditorToCharacter` must subtract the top padding, or the line lands 10px too high (Task 3).
3. **A narrow window.** Even with glyphs, a window narrower than the toolbar puts buttons under the hide button. Set `MinWidth` so that can't happen (Task 2).
4. **The icon at 16px in the tray.** It must stay readable at small sizes: plain shapes, and an outline dark enough for a light taskbar (Task 1, checked visually).
5. **Icon loading.** `System.Drawing.Icon` on .NET Framework is fussy about PNG-compressed frames at small sizes. Use BMP/DIB frames for every size up to 48 and PNG only for 256 (Task 1).

### Task 1: App icon

**Files:**
- Create: `tools/make_icon.py`
- Create: `Scratchpad/Assets/Scratchpad.ico` (generated, committed)
- Modify: `Scratchpad/Scratchpad.csproj`, `Scratchpad/MainWindow.xaml`, `Scratchpad/SettingsWindow.xaml`, `Scratchpad/TrayIconManager.cs`

**Interfaces:**
- Produces: the pack URI `pack://application:,,,/Assets/Scratchpad.ico`, used by both windows' `Icon` and by the tray.

- [ ] **Step 1: Write `tools/make_icon.py`.**
  - It writes `Scratchpad/Assets/Scratchpad.ico` relative to the repo root, using only the stdlib.
  - Frames: 16, 20, 24, 32, 40 and 48 as 32bpp BGRA DIBs (BITMAPINFOHEADER with height ×2, bottom-up rows, plus a 1bpp AND mask padded to 32 bits per row), and 256 as PNG.
  - Draw each size directly with 4×4 supersampled coverage; don't downscale from 256.
  - Geometry, as fractions of size `s`:
    - The note is a square inset by `max(1px, 0.0625s)`, filled `#FFE066`, with a ~1px outline `#A88A10`.
    - The bottom-right corner is folded over: a triangle with legs `0.28s`. The cut-off corner is transparent, and the flap is filled `#F0C419` with the same outline.
    - Three ink lines in `#5C4F1A`, `0.07s` thick, at `y = 0.33s, 0.50s, 0.67s`. They span `x = 0.24s → 0.76s`, except the last, which ends at `0.56s` so it clears the fold.
  - Add a one-line comment at the top saying how to regenerate the icon.
- [ ] **Step 2: Run it and inspect.**
  - Run `python3 tools/make_icon.py`.
  - Then run a small check that parses the ICONDIR and confirms 7 entries with sizes `[16,20,24,32,40,48,256]`.
  - Also write the 256 frame and a 16 frame (upscaled ×8 with nearest neighbour) to the session scratchpad as PNGs, and look at them. The 16px version should still read as a yellow note with lines.
- [ ] **Step 3: Wire it in.**
  - csproj: add `<ApplicationIcon>Assets\Scratchpad.ico</ApplicationIcon>` and `<ItemGroup><Resource Include="Assets\Scratchpad.ico" /></ItemGroup>`.
  - `MainWindow.xaml` and `SettingsWindow.xaml`: `Icon="pack://application:,,,/Assets/Scratchpad.ico"`.
  - `TrayIconManager`: load the icon from `System.Windows.Application.GetResourceStream(new Uri(...)).Stream` with `new System.Drawing.Icon(stream, SystemInformation.SmallIconSize)`.
    - Wrap the load in try/catch and fall back to `SystemIcons.Application`.
    - Dispose the loaded icon in `Dispose()`, but only if it isn't the system one.
- [ ] **Step 4: Build.** Run `dotnet build Scratchpad/Scratchpad.csproj`. Expected: `0 Error(s)`.
- [ ] **Step 5: Commit** `feat: add a Post-it app icon for tray, window and exe`.

  - Their setters: `FontFamily="Segoe MDL2 Assets"`, `FontSize="14"`, `Width="32"`, `Height="28"`, `Padding="0"`, `Margin="2,4"`.

### Task 3: Space around the note text

**Files:**
- Modify: `Scratchpad/MainWindow.xaml`, `Scratchpad/MainWindow.xaml.cs` (`ScrollEditorToCharacter` ~373, `ApplyPreviewBackground` ~401)

- [ ] **Step 1: Add the padding in XAML.**
  - In `Window.Resources`, add `<Thickness x:Key="NoteTextPadding">10,8,10,8</Thickness>`.
  - `EditorTextBox`: `Padding="{StaticResource NoteTextPadding}"`.
  - `PreviewViewer`: `Margin="{StaticResource NoteTextPadding}"`. Put it on the viewer, not the outer ScrollViewer's `Padding`, so the space scrolls with the content and the navigator's extent maths still lines up. A Margin sits outside the zoom `LayoutTransform`, so it stays 10px at every zoom, the same as the editor.
- [ ] **Step 2: Remove the preview's own page padding.**
  - In the post-render step that sets the document background (`ApplyPreviewBackground`), also set `PreviewViewer.Document.PagePadding = new Thickness(0)`. Otherwise the FlowDocument's automatic page padding adds to the margin.
  - Update the method's comment to cover both settings. Don't rename it.
- [ ] **Step 3: Subtract the padding when scrolling.**
  - In `ScrollEditorToCharacter`, scroll to `Math.Max(0, EditorTextBox.VerticalOffset + rect.Top - EditorTextBox.Padding.Top)`.
  - Add a one-line comment saying the target line should land below the padding, not under it.
  - This also fixes the deferred "overshoots by TextBox padding" nit.
- [ ] **Step 4: Build.** Run `dotnet build Scratchpad/Scratchpad.csproj`. Expected: `0 Error(s)`.
- [ ] **Step 5: Commit** `feat: give the note text room to breathe`.
