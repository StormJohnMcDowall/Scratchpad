# UI Polish (Batch 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three changes:
- a tidier Settings window;
- a date-format box that is visible in dark mode and flags formats it can't use;
- a fuller tray menu.

**Architecture:**
- Core (unit-tested): `DateStamp` gains an overload that also reports whether the format was used, left blank, or rejected.
- Shell (compile-only in the sandbox), split three ways:
  - Settings XAML window properties;
  - the date example line, using the new status;
  - the tray menu, which calls a new `MainWindow.OpenSettingsFromTray()`.

**Tech Stack:** WPF on .NET Framework 4.8, plus WinForms `ContextMenuStrip` for the tray. Core is netstandard2.0 with xUnit tests.

**Spec:** a small change agreed in chat on 2026-11-03, so there is no spec document. Reproduced:

6. **Settings window:**
   - It fits its content's height.
   - It can't be resized, and has no minimise/maximise buttons.
   - It has no taskbar button.
7. **Date format box:**
   - In dark mode the box uses the darker toolbar shade. The editor is unaffected.
   - The example line reads:
     - `Today: Tue 3 Nov` for a valid format;
     - `Using the default: Tue 3 Nov` when the box is blank;
     - `Not a valid format, so Date uses: Tue 3 Nov` in a warning colour when .NET rejects the format.
   - What Date inserts doesn't change.
8. **Tray menu:**
   - The items are **Show** (bold; the double-click default), **Settings…**, a separator, then **Exit**.
   - Settings… shows the note first, then opens Settings centred on it.
   - Non-goals: dark styling for the tray menu, and any change to light-mode Settings beyond the above.

## Global Constraints

- No new NuGet dependencies.
- Example-line copy must match exactly: `Today: `, `Using the default: `, `Not a valid format, so Date uses: `, each followed by the formatted date.
- The tray item text is exactly `Show`, `Settings…` (U+2026 ellipsis) and `Exit`.
- `DateStamp.Format(format, date, culture)`, the existing 3-argument overload, keeps its behaviour and its tests.

## Review Focus

1. **Tray Settings… when the note has never been shown since startup.** The note's saved position is only applied in `Window_Loaded`, which runs *after* `Show()` returns. Settings must open centred on the note's real position, not on Windows' default position. Opening is deferred to `DispatcherPriority.Background` (Task 4).
2. **Tray Settings… while Settings is already open.** It must bring the existing window forward, not open a second one. Reuse the single-instance logic (Task 4).
3. **Typing from a rejected format back to a valid one.** The warning colour must clear. In dark mode the text must go back to the paper's ink colour, not the system black (Task 2, `ClearValue`).
4. **Switching theme while the warning is shown.** The warning colour must follow the theme live, so set it as a resource reference (Task 2).
5. **Reset to defaults while a rejected format is shown.** The line must go back to `Today: …`. `ShowSettings` already calls `UpdateDateExample`; keep that path (Task 2).

### Task 1: DateStamp reports how the format was used

**Files:**
- Modify: `Scratchpad.Core/DateStamp.cs`
- Test: `Scratchpad.Core.Tests/DateStampTests.cs`

**Interfaces:**
- Produces:
  - `public enum DateFormatStatus { Valid, Blank, Rejected }`, in namespace `Scratchpad.Core`, in `DateStamp.cs`.
  - `public static string Format(string format, DateTime date, IFormatProvider culture, out DateFormatStatus status)`.
  - The existing 3-argument `Format` delegates to the new overload.

- [ ] **Step 1: Write the failing tests** in `DateStampTests.cs`, reusing `Tuesday` and `EnGb`:

```csharp
[Fact]
public void Format_ValidFormat_ReportsValid()
{
    Assert.Equal("2026-11-03", DateStamp.Format("yyyy-MM-dd", Tuesday, EnGb, out var status));
    Assert.Equal(DateFormatStatus.Valid, status);
}

[Theory]
[InlineData(null)]
[InlineData("")]
[InlineData("  ")]
public void Format_NullOrWhitespace_ReportsBlank(string format)
{
    Assert.Equal("Tue 3 Nov", DateStamp.Format(format, Tuesday, EnGb, out var status));
    Assert.Equal(DateFormatStatus.Blank, status);
}

[Theory]
[InlineData("%")]
[InlineData("ddd \\")]
public void Format_InvalidFormat_ReportsRejected(string format)
{
    Assert.Equal("Tue 3 Nov", DateStamp.Format(format, Tuesday, EnGb, out var status));
    Assert.Equal(DateFormatStatus.Rejected, status);
}
```

- [ ] **Step 2: Run the tests.** Run `dotnet test Scratchpad.Core.Tests --filter DateStampTests`. Expected: a compile failure, because `DateFormatStatus` and the 4-argument `Format` don't exist yet.
- [ ] **Step 3: Implement the enum and the overload.** Move the existing logic into the 4-argument overload and make the 3-argument one call it and discard the status. Give the enum a one-line doc comment per member.
- [ ] **Step 4: Run the tests again.** Run `dotnet test Scratchpad.Core.Tests`. Expected: all pass (103 + 6 = 109).
- [ ] **Step 5: Commit** `feat: report whether a date format was used, blank or rejected`.
